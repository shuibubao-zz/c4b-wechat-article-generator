# 审计说明：文件命名与"空文件"告警

给评审与自动盘点工具看的说明，避免把设计上的选择误判成缺陷。

## 1. 为什么有些文件不叫 `卢怡然_C4B_xxx`

挑战的命名规范 `姓名_C4B_内容描述.扩展名` 针对的是**交付物**。本包里：

- **交付物**（7 个）全部符合规范：
  `卢怡然_C4B_wechat-publisher.skill`、`卢怡然_C4B_文章源文件.md`、
  `卢怡然_C4B_output.html`、`卢怡然_C4B_文章链接.md`、`卢怡然_C4B_教学说明.md`、
  `卢怡然_C4B_AI日志.md`、`卢怡然_C4B_拿来说明.md`
  （另附 `卢怡然_C4B_AAR.md` 与 `README.md`）

- **技能包内部文件**保留功能名（`scripts/convert_to_wechat.py`、`SKILL.md` 等）：
  它们是一个可被安装到 `~/.workbuddy/skills/` 的技能，文件名即调用入口，
  改成中文命名会让技能无法被正确加载。这是技能包的通行约定，不是遗漏。

- **`_starter/`** 是 starter kit 的**原样副本**（SHA-256 可核对），
  一个字节都没改，用于对照"我改了什么"。改了名就失去了对照价值。

- **`evidence/`** 是实测留档，文件名按"内容"命名以便检索。

## 2. 关于自检器报告的两个"假异常"（自指问题）

`evidence/submit_guard_audit.txt` 由 challenge-submit-guard 生成，存在两个自指假象，都不是交付物缺陷：

1. **0 字节误报**：若报告文件是本次运行的输出重定向目标，扫描那一刻它正被写入、大小为 0。
2. **「有深度」信号震荡**：该信号靠字面子串匹配。扫描时若语料里**没有**历史报告，
   关键词"有深度"无法自然命中 → 判缺失（粗估 8.3）；而报告写入文件夹后，其"缺失信号"列
   恰好含有"有深度"三个字，**再次扫描就会自指命中** → 粗估虚升至 16.7。
   本留档是**扫描时不含报告自身**的诚实版本（8.3）。这正是 C4A 里"降级路径恒真空转"
   敲过的同一口钟：自检器引用自身产物时，结论不可信。
   另注：该工具自述为"机器粗估，非官方评分"；文章的深度（现象→原因→解法三层、
   可复核实测数据、明确观点）请人工复核，不依赖这个关键词探测器。
